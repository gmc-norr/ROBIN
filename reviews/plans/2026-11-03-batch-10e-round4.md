## Fixes

1. **Finalize lists every kept claim folder:** a new module helper `_kept_claims(sample_dir)` gives the claim folders holding `incomplete.txt`. Finalize calls it under the accumulation lock, after its finish. It lists the folders it saw before that are still there, plus these. `_finish_commit` returns its entries only, and the two add-up callers drop `[0]`.
2. **`keep_claim` makes its folder again:** when `incomplete.txt` is not in the step's claim folder, `_install` makes the folder and writes it, with the batch's BAMs as counted and the step's problem. `_retire` already syncs the folder and `_staging/` before deleting the list.
3. **Synced before every list:** the two syncs (`_sync_dir(batch_dir)`, `_sync_dir(staging_dir)`) move out of `if batch_bam:` and come after the batch BAM's file syncs, before the list is written.
4. **An error with no text:** `batch_bam_error = str(e) or type(e).__name__`, and `bam_problem` uses it.

## Rulings

- **A kept claim folder is listed by every finalize until someone deals with it,** whoever kept it. This was already so for a folder present before finalize's wait; now it is also so for one kept after.
- **The claim folder is synced before a list that drops it.** This is not needed, but harmless (two more syncs in a commit without a batch BAM). One rule for every list is simpler than two.
